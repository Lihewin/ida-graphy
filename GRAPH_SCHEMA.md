# IDA-Graphy Graph Schema (AI Reference)

This document describes the graph data model produced by IDA-Graphy, including node types, properties, and ID generation rules. It is intended for AI systems that read the embedded LadybugDB database file (e.g., `graph.lbug`).

## Scope

- Only describes the graph schema generated by the analysis pipeline.
- Focuses on node types, properties, and ID rules.
- Edge types and their key properties are included for query construction.

## Node Types

### 1) Binary

Represents a physical binary file.

Label: `:Binary`

Primary ID:
- `hash` (SHA-256 of the full file bytes)

Properties:
- `hash` (String) Unique ID of the binary. Generated as SHA-256 of the file content.
- `name` (String) File name, e.g., `fw_engine.exe`.
- `base_addr` (Long) Image base address used for VA/RVA conversion.
- `arch` (String) Architecture, e.g., `x86_64`, `ARM`.
- `compile_ts` (Long) Compile timestamp (if available).

ID rule:
- `hash = sha256(file_bytes)`

### 2) Function

Represents a function (behavioral node).

Label: `:Function`

Primary ID:
- `uid` (MD5 of binary hash + RVA)

Properties:
- `uid` (String) Unique function ID across binaries.
- `rva` (Long) Function start RVA.
- `name` (String) Symbol name or `sub_XXXX`.
- `size` (Int) Function size in bytes.
- `is_lib` (Boolean) True if identified as library function (AI should often ignore).
- `func_type` (String) One of `NORMAL`, `IMPORT`, `EXPORT`, `THUNK`.
- `signature` (String) Function prototype, if available.
- `complexity` (Int) Cyclomatic complexity (if available).
- `binary_id` (String) Redundant cache of owning Binary `hash` for fast filtering.
- `decompiled_file` (String) Relative path to the primary decompile artifact, when exported.
- `pseudocode_hash` (String) SHA-256 of the exported pseudocode/content used for change detection.

ID rule:
- `uid = md5(binary_hash + "_" + rva_hex)`
- `rva_hex` is lowercase hex without `0x` prefix.

func_type rules:
- `EXPORT`: listed in the export table.
- `IMPORT`: thunk that jumps into `.idata` or name contains `__imp_`.
- `THUNK`: IDA thunk that is not an import.
- `NORMAL`: regular function.

### 3) DataSlot

Represents a persistent state element. Two kinds:
- Struct member (cross-binary shared)
- Global variable (binary-private)

Label: `:DataSlot`

Primary ID:
- `uid`

Properties:
- `uid` (String) Unique ID, rule depends on kind.
- `base_type` (String) Struct name or `GLOBAL`.
- `offset` (Int) Flattened absolute offset (decimal).
- `size` (Int) Width in bytes (1/2/4/8...)
- `name` (String) Readable name, e.g., `status`, `flags`, `g_Config`.
- `is_global` (Boolean) True for global variable, False for struct member.
- `struct_file` (String) Relative path to the exported structure definition, when available.

ID rules:
- Struct member: `uid = md5(struct_name + "_" + offset_decimal)`
  - Struct name is normalized (no `struct` prefix).
  - Offset is a decimal integer.
- Global variable: `uid = md5(binary_hash + "_GLOBAL_" + rva_hex)`

### 4) String

Represents a constant string used as a semantic anchor.

Label: `:String`

Primary ID:
- `hash` (MD5 of string content)

Properties:
- `hash` (String) Unique string ID.
- `content` (String) Cleaned string content.
- `encoding` (String) Encoding, e.g., `ASCII`, `UTF-16`.

ID rule:
- `hash = md5(string_content_utf8)`

### 5) ExportArtifact

Represents a file exported by IDA-Graphy and makes file access explicit for AI tools.

Label: `:ExportArtifact`

Primary ID:
- `uid`

Properties:
- `uid` (String) Stable artifact ID.
- `owner_id` (String) Owning Binary `hash`, Function `uid`, or DataSlot `uid`.
- `owner_type` (String) One of `Binary`, `Function`, `DataSlot`.
- `artifact_type` (String) One of `decompile`, `structure`, `strings`, `imports`, `exports`, `structure_summary`, `decompile_failures`, `ghidra_decompile`.
- `relative_path` (String) Path relative to the project directory, e.g., `exports/foo/decompile/<uid>_name.c`.
- `content_hash` (String) SHA-256 of the file content when available.
- `binary_id` (String) Owning Binary `hash`.
- `binary_name` (String) Owning binary file name.
- `status` (String) `exported` or `failed`.
- `error` (String) Export/decompilation error text for failed or fallback artifacts.

ID rule:
- `uid = md5(binary_id + owner_type + owner_id + artifact_type + relative_path + status)`

## Edge Types

### CONTAINS

Physical ownership relation.

Paths:
- `(:Binary)-[:CONTAINS]->(:Function)`
- `(:Binary)-[:CONTAINS]->(:DataSlot {is_global:true})`
- `(:Binary)-[:CONTAINS]->(:String)`

Key properties:
- `from_id` (Binary `hash`)
- `to_id` (child node ID)

### CALLS

Function call relation.

Path:
- `(:Function)-[:CALLS]->(:Function)`

Properties:
- `from_id` (caller `uid`)
- `to_id` (callee `uid`)
- `call_type` (DIRECT, INDIRECT, TAIL)
- `count` (Int) Number of calls observed
- `loop_depth` (Int) Loop nesting depth from Hex-Rays ctree, 0 means not in a loop

### LINKS_TO

Dynamic linking relation, connects import to export across binaries.

Path:
- `(:Function {func_type:"IMPORT"})-[:LINKS_TO]->(:Function {func_type:"EXPORT"})`

Properties:
- `from_id` (import `uid`)
- `to_id` (export `uid`)
- `dll_name` (String)
- `func_name` (String)

### REFERENCES

Function uses a string.

Path:
- `(:Function)-[:REFERENCES]->(:String)`

Properties:
- `from_id` (function `uid`)
- `to_id` (string `hash`)

### WRITES

Function writes to a state element.

Path:
- `(:Function)-[:WRITES]->(:DataSlot)`

Properties:
- `from_id` (function `uid`)
- `to_id` (DataSlot `uid`)
- `op_type` (ASSIGN, OR, AND, ADD)
- `const_val` (String) The written value if known
- `loc` (Long) Instruction RVA

### READS

Function reads a state element.

Path:
- `(:Function)-[:READS]->(:DataSlot)`

Properties:
- `from_id` (function `uid`)
- `to_id` (DataSlot `uid`)
- `condition` (Boolean) True if used in branch/loop conditions
- `op_type` (String) CMP/TEST/MOV/etc.
- `const_val` (String) Comparison constant if any
- `loc` (Long) Instruction RVA

### HAS_ARTIFACT

Connects graph entities to exported files.

Paths:
- `(:Binary)-[:HAS_ARTIFACT]->(:ExportArtifact)`
- `(:Function)-[:HAS_ARTIFACT]->(:ExportArtifact)`
- `(:DataSlot)-[:HAS_ARTIFACT]->(:ExportArtifact)`

Properties:
- `from_id` (owner ID)
- `to_id` (`ExportArtifact.uid`)

## Notes for Query Authors

- Use Binary `hash` as the top-level scope filter.
- For cross-binary struct member correlation, query DataSlot with `is_global=false`.
- For global variables, always join by `binary_id` or Binary `hash`.
- `func_type` and `is_lib` are the fastest filters when exploring call graphs.
- Prefer `ExportArtifact.relative_path` over inferred paths when reading exported files.
- Treat `ghidra_decompile` as supplemental fallback output with provenance, not as Hex-Rays ctree-equivalent output.

Example artifact lookup:

```cypher
MATCH (f:Function)-[:HAS_ARTIFACT]->(a:ExportArtifact)
WHERE f.name = "target_function"
RETURN f.uid, f.name, a.artifact_type, a.relative_path, a.status, a.error;
```
