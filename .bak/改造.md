
### 一、 节点定义 (Node Definitions)

#### 1. `Binary` (容器节点)

**物理层**。代表一个可执行文件或动态库。

* **Label:** `:Binary`
* **ID 生成规则:** `Hash(FileContent)` (推荐 MD5 或 SHA256)

| 属性 Key | 类型 | 说明 |
| --- | --- | --- |
| `hash` | String | **主键**。全局唯一标识。 |
| `name` | String | 文件名 (e.g., `fw_engine.exe`)。 |
| `base_addr` | Long | 加载基址 (e.g., `0x140000000`)。用于 RVA <-> VA 转换。 |
| `arch` | String | 架构 (e.g., `x86_64`, `MIPS`)。 |
| `compile_ts` | Long | 编译时间戳。用于判断版本迭代。 |

#### 2. `Function` (行为节点)

**逻辑层**。代码的执行单元。

* **Label:** `:Function`
* **ID 生成规则:** `Hash(BinaryHash + "_" + RVA)`

| 属性 Key | 类型 | 说明 |
| --- | --- | --- |
| `uid` | String | **主键**。跨二进制唯一。 |
| `rva` | Long | 相对虚拟地址 (Function Start RVA)。 |
| `name` | String | 符号名 (e.g., `Process_Packet`) 或 `sub_XXXX`。 |
| `size` | Int | 函数长度 (bytes)。 |
| `is_lib` | Boolean | **AI 过滤器**。是否为标准库函数 (`True` = 忽略)。 |
| `func_type` | String | `'NORMAL'`, `'IMPORT'`, `'EXPORT'`, `'THUNK'`。 |
| `signature` | String | 函数原型 (e.g., `int func(void* ctx)`). |
| `complexity` | Int | 圈复杂度。 |
| `binary_id` | String | **[冗余优化]** 所属 Binary 的 hash，用于快速过滤。 |

有关func_type：
```
def classify_function(func_ea):
    # 1. 检查是否在导出表
    if is_in_export_table(func_ea):
        return "EXPORT"
    
    # 获取函数标志
    flags = ida_funcs.get_func(func_ea).flags
    
    # 2. 检查是否为 Thunk 类型 (IDA 认为的跳转函数,即里面全是jmp的跳转函数)
    if flags & ida_funcs.FUNC_THUNK:
        # 深入分析：它跳到了哪里？
        target_ea = get_thunk_target(func_ea)
        
        # 如果跳到了 .idata 段 (导入表数据区) 或者 名字包含 __imp_
        if is_in_idata(target_ea) or "__imp_" in get_func_name(func_ea):
            return "IMPORT" # 这是一个导入桩
        
        # 否则，它只是一个内部跳转
        return "THUNK"
        
    # 3. 普通业务函数
    return "NORMAL"
```


#### 3. `DataSlot` (状态节点)

**数据层**。业务逻辑的持久化载体。分为“结构体成员”和“全局变量”。

* **Label:** `:DataSlot`
* **ID 生成规则:**
* **Struct:** `Hash(BaseType + "_" + AbsoluteOffset)` (跨二进制共享)
* **Global:** `Hash(BinaryHash + "_GLOBAL_" + RVA)` (二进制私有)



| 属性 Key | 类型 | 说明 |
| --- | --- | --- |
| `uid` | String | **主键**。 |
| `base_type` | String | 结构体名 (e.g., `SessionEntry`) 或 `'GLOBAL'`。 |
| `offset` | Int | 扁平化的绝对偏移量 (Decimal)。 |
| `size` | Int | 数据宽度 (1, 2, 4, 8 bytes)。 |
| `name` | String | 可读名称 (e.g., `status`, `flags`, `g_Config`)。 |
| `is_global` | Boolean | `True` 表示全局变量，`False` 表示结构体成员。 |

#### 4. `String` (语义节点)

**语义层**。常量字符串，用于“锚定”业务含义。

* **Label:** `:String`
* **ID 生成规则:** `Hash(Content)`

| 属性 Key | 类型 | 说明 |
| --- | --- | --- |
| `hash` | String | **主键**。 |
| `content` | String | 字符串实际内容 (需清洗，去除乱码)。 |
| `encoding` | String | `'ASCII'`, `'UTF-16'` 等。 |

### 二、 边关系定义 (Relationships)

边的设计侧重于**“动作意图”**，这是 Agent 理解代码逻辑的关键。

#### 1. 物理归属 (`CONTAINS`)

* **路径:** `(:Binary) -[:CONTAINS]-> (:Function)`
* **路径:** `(:Binary) -[:CONTAINS]-> (:DataSlot {is_global:True})`
* **路径:** `(:Binary) -[:CONTAINS]-> (:String)`
* **作用:** 维护物理拓扑，用于“模块级”分析。

#### 2. 控制流 (`CALLS`)

* **路径:** `(:Function) -[:CALLS]-> (:Function)`
* **属性:**
* `type`: `'DIRECT'` (直接调用), `'INDIRECT'` (虚表/指针), `'TAIL'` (尾调用)。
* `count`: `Int` (调用次数，高频调用可能暗示循环)。



#### 3. 动态链接 (`LINKS_TO`)

* **路径:** `(:Function {type:'IMPORT'}) -[:LINKS_TO]-> (:Function {type:'EXPORT'})`
* **作用:** 将不同 Binary 的逻辑缝合起来 (IAT -> EAT)。

#### 4. 语义引用 (`REFERENCES`)

* **路径:** `(:Function) -[:REFERENCES]-> (:String)`
* **作用:** 函数使用了该字符串 (参数引用或局部引用)。

#### 5. 核心业务流：写操作 (`WRITES`)

**定义:** 函数**修改**了某个状态。

* **路径:** `(:Function) -[:WRITES]-> (:DataSlot)`
* **属性 (核心):**
* `op_type`: `'ASSIGN'` (赋值), `'OR'` (置位), `'AND'` (清位), `'ADD'` (累加)。
* `const_val`: `String` (e.g., `'0x80'`, `'1'`)。**关键**：记录具体写入了什么值。
* `loc`: `Long` (操作发生的指令 RVA)。



#### 6. 核心业务流：读操作 (`READS`)

**定义:** 函数**使用**了某个状态。

* **路径:** `(:Function) -[:READS]-> (:DataSlot)`
* **属性 (核心):**
* `condition`: `Boolean`。**关键**：`True` 表示该读取发生在 `if/switch/loop` 判断中（控制流依赖）；`False` 表示仅用于数据计算或传递。
* `op_type`: `'CMP'`, `'TEST'`, `'MOV'`。
* `const_val`: `String` (e.g., `if (state == 3)` 中的 `'3'`)。



### 二、哈希算法
为了保证数据的一致性和跨二进制的逻辑关联，请严格遵守以下输入构造格式（使用 UTF-8 编码）：

1. Binary 节点 (容器)
这是物理文件的唯一指纹。

算法: SHA-256

输入: 文件的完整二进制内容 (Raw Bytes)。

ID 示例: e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855

2. Function 节点 (行为)
函数必须绑定到特定的 Binary，因为不同版本的 kernel32.dll 中，同一个 RVA 可能对应完全不同的代码。

算法: MD5

输入: {Binary_SHA256}_{RVA_Hex}

Binary_SHA256: 上一步生成的 Binary ID。

RVA_Hex: 函数起始相对虚拟地址（小写 hex，不带 '0x'，如 1000）。

ID 生成伪代码:

Python
input_str = f"{binary_sha256}_{hex(func_rva)[2:].lower()}"
node_id = hashlib.md5(input_str.encode()).hexdigest()
3. DataSlot 节点 (结构体成员 - 通用型)
这是关键设计。 结构体成员 ID 不包含 Binary Hash。这样做的目的是为了让不同二进制中对同一个结构体的访问，能够汇聚到同一个节点上。

算法: MD5

输入: {StructName}_{AbsoluteOffset_Decimal}

StructName: 结构体名称（需标准化，去除 struct 前缀，如 SessionEntry）。

AbsoluteOffset_Decimal: 扁平化后的绝对偏移量（十进制整数）。

ID 生成伪代码:

Python
input_str = f"{struct_name}_{offset_int}"
node_id = hashlib.md5(input_str.encode()).hexdigest()
4. DataSlot 节点 (全局变量 - 私有型)
全局变量是物理存在的内存块，必须绑定到 Binary，否则会导致不同 DLL 的同名全局变量冲突。

算法: MD5

输入: {Binary_SHA256}_GLOBAL_{RVA_Hex}

ID 生成伪代码:

Python
input_str = f"{binary_sha256}_GLOBAL_{hex(global_rva)[2:].lower()}"
node_id = hashlib.md5(input_str.encode()).hexdigest()
5. String 节点 (语义锚点)
用于去重存储字符串。

算法: MD5

输入: String_Content

ID 生成伪代码:

Python
node_id = hashlib.md5(string_content.encode('utf-8')).hexdigest()


示例代码
```python
import hashlib

class NodeIDGenerator:
    def __init__(self, binary_content=None, binary_hash=None):
        """
        初始化：必须提供 binary_content 或者 已经计算好的 binary_hash
        """
        if binary_hash:
            self.binary_hash = binary_hash
        elif binary_content:
            self.binary_hash = hashlib.sha256(binary_content).hexdigest()
        else:
            raise ValueError("Must provide binary content or hash")

    def _md5(self, s):
        """辅助函数：计算 MD5"""
        return hashlib.md5(s.encode('utf-8')).hexdigest()

    def get_binary_id(self):
        """获取 Binary 节点 ID (SHA256)"""
        return self.binary_hash

    def get_function_id(self, rva):
        """
        获取 Function 节点 ID
        Scope: Binary 私有
        Input: BinaryHash + RVA
        """
        # 统一使用小写 hex，不带 0x
        rva_str = hex(rva)[2:].lower()
        return self._md5(f"{self.binary_hash}_{rva_str}")

    def get_struct_slot_id(self, struct_name, offset):
        """
        获取 结构体 DataSlot ID
        Scope: 全局通用 (跨 Binary)
        Input: StructName + Offset
        """
        # 结构体 DataSlot 不绑定 Binary Hash
        return self._md5(f"{struct_name}_{int(offset)}")

    def get_global_slot_id(self, rva):
        """
        获取 全局变量 DataSlot ID
        Scope: Binary 私有
        Input: BinaryHash + GLOBAL + RVA
        """
        rva_str = hex(rva)[2:].lower()
        return self._md5(f"{self.binary_hash}_GLOBAL_{rva_str}")

    def get_string_id(self, content):
        """获取 String 节点 ID"""
        return self._md5(content)

# --- 使用示例 ---
# 假设我们正在分析 kernel32.dll
gen = NodeIDGenerator(binary_hash="a1b2c3d4e5f6...")

# 1. 生成函数 ID (0x1000)
func_id = gen.get_function_id(0x1000)
print(f"Function Node ID: {func_id}")

# 2. 生成结构体成员 ID (Session.status, offset 8)
# 注意：即便在 user32.dll 中调用，生成的 ID 也是一样的，从而实现关联
slot_id = gen.get_struct_slot_id("SessionEntry", 8)
print(f"Struct Slot ID:   {slot_id}")
```
